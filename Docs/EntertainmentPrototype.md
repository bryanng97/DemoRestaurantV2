# Entertainment prototype

Guests first look for dining seats. If none is available, they reserve a free, working Entertainment piece with a reachable front access tile. They use the machine for 30 seconds, automatically pay one coin and leave. No unhappy-seat penalty applies. One guest can reserve each machine; machines break at their catalog break count and cleaners or a player tap repair them. NPC hand motion, a localized activity/progress indicator and native on/off/broken furniture timelines show the activity.

The private catalog importer now includes coin-priced interactive items: Retro Arcade Machine, Crazy Planets Pinball and Wishing Well. Original purchase prices, unlock levels and break counts come from the supplied XML. Their art remains ignored. `furniture_export.py --entertainment-states` bakes the named native states without executing SWF code. The human-played Snake/Cave minigames are separate and have not been implemented.

`rules.json` holds the new activity duration and payout. The economy workbook, existing dish prices, XP rules and level cap are unchanged. Unlike the original functional-use bonus, this prototype adds no entertainment XP, meal count or ingredients. Machine wear survives moves, Undo and layout snapshots, and loads with the existing saved functional-use counters. Storing/rebuying copies currently uses aggregate furniture ownership; individual inventory wear needs stable server instance IDs before launch.

Offline `LocalEconomyServer.SubmitEntertainment` validates catalog kind, the authority's payout and unique receipts. The sim enforces timing, occupancy and front access. Completed uses are recorded as `EntertainmentIncome` ledger entries. Online they require server validation before being treated as confirmed income. The backend must validate ownership, placed instance, reachability, elapsed activity and wear; pay once per idempotent receipt; and return its wallet and wear. Client coin claims and layout usage counters are not authoritative. A layout move or storage operation must not reset server wear.

Reference behavior was checked against [Customer.as](https://github.com/Dippys/Restaurant-City-client/blob/main/scripts/com/playfish/games/cooking/actors/Customer.as), [WorldRestaurantPlay.as](https://github.com/Dippys/Restaurant-City-client/blob/main/scripts/com/playfish/games/cooking/WorldRestaurantPlay.as) and [GameWorld.as](https://github.com/Dippys/Restaurant-City-client/blob/main/scripts/com/playfish/games/cooking/GameWorld.as). The original pays automatically after use; there is no accumulated coin balance requiring a player collection tap.

HUD Actions and Explore drawers start collapsed, expand into two columns and close after selecting a function. Buttons grew from 104 x 100 to 156 x 148, with larger icons/text and separate 212 x 76 open/close handles. Opening one drawer closes the other. English, Malay and Chinese labels are supported.
